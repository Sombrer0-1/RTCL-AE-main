# 新种子同缓存消融：受外部 CPU 负载影响

双方使用相同的 128 MiB 上限缓存和推理批量反馈控制，比较多进程与边界执行结构。与 `../round2/` 属于不同时间阶段，不合并绝对耗时。

| 种子 | freshness_cached / s | boundary_cached / s | 配对加速比 |
|---|---:|---:|---:|
| 44 | 82.82 | 48.17 | 1.719 |
| 55 | 59.58 | 50.51 | 1.180 |
| 66 | 90.83 | 89.63 | 1.013 |

三对最终模型哈希逐一一致，均完成 10 次全测试集评估。缓存持久容量均为 122,960,000 字节。

三对比值均超过 1，但最后一对仅快约 1.3%。主机存在较重其他 CPU 任务，开始和结束负载见 `host_load.json`、`host_load_end.json`。不同阶段的主机负载没有被控制；本组不能证明额外收益都由调度结构导致。边界方案的跨种子耗时 CV 为 37.10%，反而高于多进程缓存方案的 20.88%，所以也不能据此宣称负载下稳定性更强。

本组出现超过 10 ms 的批延迟；推理批量策略的 10 ms 是软反馈目标，并非 deadline 保证。主报告以较早的独立主对照为依据，此处完整保留补充与负面证据。

汇总见 `summary.csv`、`paired_speedups.json`、`comparison.png`。复跑和分析命令见 [主报告](../round2/README.md)。
