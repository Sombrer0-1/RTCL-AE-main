# 第三轮设计记录（实现和正式实验前冻结）

时间：2026-09-22。基线留档：428f466。目标不是延续固定评估集缓存的加速数字，而是检验调度是否能在**独立到达、有等待时限的推理请求**下有用。

## 阅读与取舍

1. [EdgeServing, arXiv v1, 2026-05-07](https://arxiv.org/abs/2605.05527)：读取全文 HTML。其时分 GPU 执行和队列状态预测提示：调度应考虑决策对待服务队列的整体影响。本实验借鉴这一问题建模方向，但不使用 early exit，不改变模型精度来换时延，也不声称复现该论文。
2. [Age of Information-Oriented Link Scheduling in Device-to-Device Networks, IEEE TWC, 2025](https://doi.org/10.1109/TWC.2025.3572690)：读取出版方摘要，未获取期刊全文。它结合信息年龄、Lyapunov 漂移与学习策略，提示不能只看即时吞吐，应关注长期未服务积累。这里用“训练服务欠账”表示长期资源需求，不将其论文的稳定性结论移植过来。
3. [Model predictive control with residual learning and real-time disturbance rejection: Design and experimentation, Control Engineering Practice, 2025](https://doi.org/10.1016/j.conengprac.2025.106587)：读取出版方摘要/Highlights，全文访问未成功。借鉴控制工程的残差建模与扰动补偿结构；本实验不实现其 GP/GESO 控制器。

这些是近期参考，不是全面文献综述或新颖性证明。候选设计还借鉴排队论的欠账递推与事件触发控制。早退、减少训练样本、跳过超时请求均不采用，因为会改变工作量或准确率口径。

## 主要 idea

在 **minibatch 完成的安全边界** 服务推理，避免旧方案整段 experience 不提供服务。所有策略共享同一个单 GPU 执行器、相同模型和训练更新顺序。推理数据每次重新读取/变换/传输，禁用 GPU 数据缓存；每条请求选用唯一测试样本，避免重复样本缓存获益。

训练服务欠账：D <- max(0, D + rho * dt - 1_train * dt)，rho=0.7。可将其理解成生产系统的“积欠工单”：只顾推理，训练欠账会增长；持续训练则偿还欠账。它是有限任务中的调度状态，不是到达率稳定性定理。

解析策略枚举训练一步或服务 1/4/8/16/32 个已到达请求。以队列等待时间和训练欠账构造二次势函数，比较每单位预测耗时的势变化。另用近期耗时均值、波动和尾部观测形成保守估计；若预计再训练一步会侵占最老请求的剩余时间，则排除训练动作。过载时不能承诺满足全部时限；保留所有逾期请求、完整处理、完整计分。

学习变体仅加入 **6→8→1、65 参数的 CPU NumPy 网络**，预测耗时的有界对数残差。仅用已经完成的操作训练，每 8 个观测更新一次，不能读取未来到达或测试准确率。网络只影响动作排序，不能撤销解析可行性过滤。与解析策略做消融，测量推断、更新和总体控制开销；没有收益就明确记录。

## 基线与防止刷分

- FIFO：每个 minibatch 边界优先处理已有请求，最大推理批量 32。
- Slack：基于同一保守耗时估计，在最老请求余量允许时继续训练，否则服务队列；这是有竞争力的简单基线。
- Debt：上述欠账/势函数策略。
- Neural：同一欠账策略 + 65 参数残差模型。
- 旧 experience-boundary 机制作为短 pilot 反例，验证等待指标能识别只追求总耗时的方案。

不是原 AOCL 的同构实现或全面论文对比；它是新增在线请求验证轨道。原始 AOCL 和原成果保持不变。

预定主矩阵：CIFAR10 / ResNet20 / 2 epochs / 平稳请求；CIFAR10 / ResNet56 / 1 epoch / 突发请求。完整训练数据 50,000，每个 epoch 都计入训练工作量。2 个独立种子（101、202），4 个主策略，16 次 GPU 运行。共 6,000 个唯一推理样本，每次基于同一种子生成完全相同的到达时间与样本顺序；到达窗口 30 秒，SLO 分别 100 ms / 33 ms。训练最初 20 次更新作为共同 warmup，流式时钟从此启动，warmup 仍计入总耗时。

正式实验前只允许单独标记的 pilot 用于正确性和运行时可行性检查，不凭 pilot 调参挑胜率。网络在线更新，不使用任何未来标签；不同运行重新初始化。没有 GPU 独占或 CPU 隔离保证，逐次记录系统负载并轮换策略执行顺序。

主指标：到达至同步推理完成的 P50/P95/P99、全部请求的超时比例、按时完成 goodput、总耗时、训练完成时间、处理数量、在线准确率、最终快照准确率、最终模型哈希、最长训练停顿、控制开销。不得把请求排队时间排除，也不得丢弃过期请求。若同种子模型哈希不一致，先查训练等价性问题，不发布加速结论。

扩大的是训练量、网络规模、到达形态和计时口径，不跑超长原论文实验。此阶段仍只有一个数据集，不能宣称跨数据集泛化或严格实时保证。
