# 未来到达信息与训练启动机会

## 问题与控制变量

在 R4 同线程合作式 FIFO 上，仅改变已经准备好当前 minibatch、推理队列为空时的训练启动决定。请求到达后仍 FIFO 服务，每批最多 32 个；数据准备保留原合作式服务点。训练计算不可抢占。

模型与流沿用 Thor R6：SplitCIFAR10、Replay、训练 batch64、6000 个唯一测试请求、30 秒到达窗口、最终 10000 样本测试。平稳组 R20／2 epochs／100 ms SLO；突发组 R56／1 epoch／33 ms SLO。每组完整执行 1580／790 步；不改变样本、优化器、Replay、随机数状态和最终评估。各配对检查最终权重及 BN 缓冲完全一致。

## 四种策略

- `r4`：队列为空立即训练。
- `reactive100`：只看已完成响应。等待长度为 `max(0, T + I(1) - SLO)` 的安静期，再启动训练；每步主动空等累计上限 100 ms。
- `oracle100`：知道未来到达时间，用 FIFO 服务模拟比较立即训练与立即保持服务就绪的超时数。如果训练增加超时，等到下一次到达后服务，再判断；每步主动空等累计上限 100 ms。
- `oracle_unlimited`：同一个 oracle，不限制主动空等。用于显示减少超时可付出的训练进度代价。

`T` 是最近至多64次已完成训练计算段的 p90×1.1；`I(b)` 是未修改的 R4 因果推理耗时上界。所有策略都只使用过去的耗时；oracle 特权仅包含时间戳，没有未来标签、正确率、耗时或模型收益。预测范围到当前时间加 `T+I(32)`；模拟批处理和这期间新到达形成的后续排队。准备期间不主动等待。

100 ms 预算从首次训练启动判断起累计实际 sleep 时间，不扣除服务时间；耗尽后启动训练，因而不承诺零超时或总停顿小于100 ms。不受预算限制的 oracle 也必须处理完整请求流、随后完成全部训练。

这是“准确到达信息下可实现的改善”实验。局部动作比较、有限前瞻、因果耗时估计与真实运行波动决定了它不构成所有可行调度器的数学最优上界；若观察到改善，就证明存在空间，负结果则不能排除其他 oracle 策略。

## 冻结矩阵与指标

pilot：seed19，R56突发，R4与oracle100；用于检查决策确实改变、完整工作量和模型一致性。正式：seeds211、307、419；平稳比较 R4/oracle100，突发比较全部四种策略，共18次，逐种子轮换顺序。pilot 不并入正式结果。

逐请求重算超时率、P95/P99、在线正确率和按时正确率。同步报告总墙钟、训练完成时刻、30秒内完成训练步数、请求服务时的训练进度、主动空等、预算耗尽次数及控制开销。P95/P99 的组统计是逐次分位数的均值。按时正确率以全部6000个请求为分母。

总墙钟包含进程导入、初始化、全部训练、全部请求、最终评估和退出。训练完成时间以插件创建为起点；请求时间以20步warmup后的流起点为零。样本与训练阶段仍相互独立，这一实验衡量系统阻塞和实际在线准确率，不用于声称分布适应变快。

所有运行使用本机 Thor GPU0、Conda rtcl、CPU库线程1，串行执行，环境及实际命令随输出保存。保留常驻其他GPU进程，不修改其状态。
