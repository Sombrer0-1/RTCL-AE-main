# 未来信息的价值：控制训练工作量

## 研究问题

已知未来到达的纯避险策略会减少请求窗口内的训练工作。新对照以相同任务释放配额约束训练进度，测量可预测周期和精确到达时刻各自增加多少收益。

## 固定设置

Thor GPU0 / MAXN，SplitCIFAR10、R56、Replay、1 epoch、训练batch64、最多32个请求一批推理、6000个唯一请求、30秒周期突发、33 ms SLO、最终10000样本测试。全部策略完成790步，配对的最终权重及BN缓冲、请求轨迹相同。

流从完成100步训练后的同一模型状态开始，避开首次进入Replay拼批的成本突变。原始20步预热实验保留为历史对照；此阶段重跑原R4基线，不能直接把两种起点的在线正确率相减。

## 共同配额

每秒释放8或9个训练更新；当前秒配额完成后，准备好下一批输入但等待下秒释放，同时服务推理。配额保留训练数据及顺序，不改变更新内容。30秒后的配额取消，完成所有剩余工作。

若当前窗口还有`k`个更新，下一次计算段估计为`T`，之后每次完整训练／准备工作估计为`C`，则允许主动避让的时间为：

`slack = max(0, 窗口结束 − 当前时刻 − T − (k−1)×C)`

`T`沿用计算段滚动p90×1.1，`C`是R4已完成训练／准备的因果均值，扣除合作式推理服务时间。主动等待不超过slack，耗尽后必须训练；尚未完成的工作带到下一秒。所有策略使用同一条配额规则和成本公式。记录每秒实际完成量、最终配额欠账和逐请求训练进度，检查是否真的完成相近工作，而不是把配额当成硬实时保证。

## 信息层级

| 策略 | 可用到达信息 | 空队列时的行为 |
|---|---|---|
| immediate | 已到达请求 | 有配额即训练 |
| uniform | 当前时钟、已完成训练量 | 均匀分布更新，目标完成时刻为`第几个更新/配额`，不读未来到达 |
| reactive | 过去响应完成时刻 | 等待`max(0,T+I(1)−SLO)`的安静期 |
| phase | 知道每秒前200 ms是高负载时段 | 当前动作的易超时窗口覆盖高负载段时避让 |
| oracle | 未来真实到达时间戳 | FIFO模拟显示训练会增加超时时避让 |
| planned | 未来真实到达时间戳 | 在整个1秒工作窗口中安排剩余训练，优化超时数，平局时优先提前完成更新 |

phase是已知负载结构的参照，不是训练出的预测器，也不知道随机请求的具体时刻。oracle仍采用局部决策。planned每秒用过去的计算段中位数、R4训练／准备均值和推理均值建立固定成本模型，在2 ms状态桶上搜索整个窗口的训练位置；实际服务仍FIFO、实际成本仍在线观测，不会执行预测中的虚构请求。CPU规划时间计入控制耗时及总墙钟。二者均不构成连续时间、未知运行成本下的数学最优上界。训练标签、未来正确率和未来真实耗时不参与任何决策。

## 矩阵与指标

pilot：seed19、9步/秒的immediate与oracle，以及8步/秒的planned，检查完整训练、实际配额进度、模型一致性。时间回放显示，在秒初集中执行配额的immediate较弱，正式无未来对照采用uniform与reactive。正式：seeds211、307、419，每个种子重跑R4、无配额phase，以及8／9步配额下uniform、reactive、phase、oracle、planned，共36次，轮换运行顺序。所有参数在正式运行前冻结，pilot与正式均值分开。

正式主要比较同配额planned/oracle/phase对uniform及reactive的超时率、P95/P99、按时正确率、总墙钟和实际训练进度；immediate仅用于pilot与时间回放，另比较新预热起点的R4。逐秒完成量的差异与欠账必须随指标报告。相同配额还不能自动证明实际工作量一致。

先以历史实测成本做确定性时间回放，覆盖0／8／9／10步配额。回放保留训练计算及主机工作，推理时长用过去服务拟合的线性成本；执行器复用该成本为确定性真值，调度器仅观测过去完成成本。该回放不估计分类准确率，也不是新GPU实测。实际收益以完整GPU实验为准。

另在所有控制器均知道相同固定服务成本的模型中比较整窗规划，隔离未来到达信息与成本估计。各窗口解通过独立重放训练启动时刻核对请求完成、训练工作量和超时计数；固定成本结果单独报告，不作为GPU或分类结果。状态分桶与逐窗求解意味着该参照仍不等于全局连续时间最优解。

## 独立成本窗口诊断

正式矩阵启动后检查seed211的规划记录发现：100步预热后，64条历史仍有多数来自首次Replay前的低成本段。规划点估计的中位数前两个窗口仍约26 ms，而实际计算已约53 ms；原来的p90安全包络没有这个问题。保留36次原矩阵，不改变其运行实现或参数。

独立对照通过`recent_start.py`仅在规划函数内部取最近16条计算观测，调用后恢复原始64条历史；安全包络、配额控制、推理成本、训练数据、标签和目标函数保持原样。先运行seed19／8步配额的pilot，再运行seeds211、307、419下8／9步配额的6次对照。该诊断独立归档，不与原planned混合均值。
