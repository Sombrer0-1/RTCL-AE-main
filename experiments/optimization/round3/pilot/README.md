# 正确性 pilot（不与正式结果合并）

4 次真实 GPU 运行，seed 7，ResNet20 / 1 epoch / 300 个唯一请求 / 3 秒到达窗口 / 100 ms SLO。四种策略都完成 790 次训练更新、300 个请求和最终 10,000 样本评估；最终模型哈希完全相同，最终准确率均为 0.2083。

该 pilot 的目的仅是检查路径和计时口径。experience-boundary 的 P95 等待为 1816.8 ms、超时率 95.33%，说明只在整段 experience 后评估的方案不适用于此请求时限。其余三种 minibatch 策略的 P95 为 25.9–43.4 ms。不能用这一个种子的短窗口宣称胜率。

检查发现两项计量问题，在正式矩阵前修正，未调整任何调度参数或模型：

- 此目录原始 `goodput` / `stream_seconds` 的分母是“训练结束且请求已排空”的时间，混入最后一条响应之后的训练。正式版改为最后一条响应相对流式时钟的完成时间；原始 pilot 文件保持不变，不用其中 goodput 作结论。逐请求文件足以重算。
- 正式版控制开销额外计入特征构造。该计数仍不含通用请求注入/记录、模型模式和 RNG 保存恢复；这些成本计入总墙钟时间。

没有按 pilot 优胜者调参。正式设置仍为 DESIGN.md 中预定的 16 次运行。
