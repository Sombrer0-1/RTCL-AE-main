# 实现口径与可复查边界

## 执行与任务等价性

`main.py` 的 `stream_*` 模式复用单计算子进程执行路径。仅允许 SplitCIFAR10 分类，禁用动态配置与双缓冲。原始 AOCL 和第二轮模式不进入新增插件。

训练每个 minibatch 完成后同步 CUDA；下一次 `before_training_iteration` 回调决定继续训练或服务已释放请求。首次 20 次训练更新后启动请求时钟。注入器按固定时间戳开放请求，但控制器只能读取已经到达的前缀；程序来不及检查时，请求仍从预定时间开始计等待。

推理时保存/恢复 Python、NumPy、Torch RNG 和每个子模块的 train/eval 模式；使用训练模型当前参数、`eval()` 和 `no_grad()`。所有在线样本均独立读取、变换和传到 GPU，结果复制到 CPU 后才计为完成。没有 GPU 输入缓存。计入的延迟包括排队、训练阻塞、数据准备、传输、模型执行及状态恢复。

无丢弃、无早退、无减少训练更新。训练结束后等待尚未到达的请求并排空全部队列，再对完整 10,000 样本测试集做最终评估。最终模型哈希覆盖所有 `state_dict` 项，包括 BN 缓冲；比较组必须完全一致。

## 解析控制器

设已释放队列长度 Q，按到达排序的等待时间为 w_i，训练欠账为 D。每次实际操作耗时 dt 后：

```
D_next = max(0, D + (rho - I_train) * dt), rho = 0.7
```

操作耗时由在线 EWMA 估计。推理批量的基础缩放模型为 `1 + B/32`，训练为 1。近期 64 个归一化耗时构成经验上界：观测不足 4 个时取 2 × EWMA，其后取 `1.15 × max(EWMA + 2 × std, empirical_P90)`。它是风险裕量，并非可靠分位数校准或 WCET 保证。一次观测后缓存该值，候选枚举不重复计算分位数。

若“训练上界 + 当前最多 32 个请求的推理上界”侵占最老请求剩余时限，则禁止继续训练。推理候选为不超过已到达请求数的 1/4/8/16/32；不符合经验余量的批量被过滤。若连最小批量也来不及，就处理最多 32 个已有请求，所有逾期仍计入超时率。

FIFO 直接优先服务队列；Slack 在过滤允许时继续训练，否则取最大可行推理批量。Debt 对过滤后的训练/推理动作计算：

```
V = 0.5 * ((D/SLO)^2 + sum((w_i/SLO)^2))
score(action) = (V_predicted_after - V_now) / predicted_duration
```

服务 B 个请求后，它们从等待项移除，其他请求等待增加 predicted_duration；训练动作偿还欠账。选择 score 最小的动作。未到达请求不进入预测。这是借鉴排队与控制思想的启发式有限任务控制器，没有证明队列稳定性、长期训练份额或硬实时保证。持续过载时过滤器也可能长期优先推理。

## 神经辅助

Neural 保持同一过滤器，额外预测耗时的有界对数残差：

```
x = [is_train, log2(B)/5, clipped_train_cost/SLO,
     clipped_infer_cost/SLO, clipped_queue_size/32, clipped_debt/SLO]
r = 0.25 * tanh(W2 * tanh(W1*x+b1) + b2)
predicted_duration = base_cost * exp(r)
```

6→8→1，共 65 个参数；CPU NumPy 运算。仅根据已完成操作的 `log(actual/base)` 训练，目标截断到 ±0.25，每 8 个观测做一次 SGD，学习率 0.02；前 32 个观测不使用残差排名。网络无权修改经验过滤器。每个运行从同一独立 RNG 初始化，不接触训练模型 RNG、未来到达或准确率目标。

## 指标

- `wall_sec`：启动主进程至其退出的实测时间，含导入/初始化、共同 warmup、全部训练、在线请求和最终全量测试。
- `training_samples_per_wall_sec`：50,000 × epoch / wall_sec，是联合任务工作量下的有效训练样本吞吐，**不是纯训练 kernel 吞吐**，也未把 Replay 重放样本计入分子。
- `train_completion_seconds`：插件构造后至最后训练结束，含在线推理干扰及训练设置；不含之前的主进程初始化和之后的最终评估。
- `stream_seconds`：从请求时钟起点到最后一条请求完成。`goodput` 为按时完成请求数除以此时间；固定输入率下它是服务时限指标，不能视作饱和容量测量。
- `p50/p95/p99_ms` 与 `miss_rate`：对全部 6,000 个请求计算，包含逾期请求。
- `online_accuracy`：各请求服务时当前模型的正确率；调度会改变同一请求遇到的训练进度，不能要求它与最终准确率相同。
- `controller_seconds`：决策、特征构造、耗时模型和神经更新的 CPU 墙钟累计。不含通用请求注入/记录及模型模式/RNG 保存恢复；这些成本都包含在总墙钟时间。
- `max_train_pause_seconds`：两次连续训练更新之间的最大停顿，含推理和数据/experience 准备；不含训练已结束后的排空阶段。

训练数据加载和 experience 管理处于回调之外，因此尚不能在其中抢占服务。经验耗时裕量也无法消除未曾出现的主机卡顿。分析脚本记录超时请求是否在 epoch 边界进度被服务，这仅是关联诊断，不是根因证明。

两个正式设置同时改变了模型/训练轮数、流量形态和 SLO，属于两组联合压力条件，不是完整因子设计。只能在同一设置内做策略对比，不能把设置间差异单独归因于模型深度或突发性。两种子结果也不构成统计显著性或长期稳定性证明。

`guard_overrides` 是内部调试计数：FIFO 不使用过滤，Slack 只计完全不可行回退，Debt/Neural 还计训练动作被过滤。它的模式间语义不同，不用于横向性能结论。
